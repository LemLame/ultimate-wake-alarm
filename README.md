# アルティメット目覚まし / Ultimate Wake Alarm

**止めても3分後にもう一度。スヌーズを寝過ごす人のための二段確認アラーム。**

Googleカレンダーに起床予定を入れると、その時刻にAndroid端末で鳴るアラームです。空いているタブレットを専用の起床端末として使えます。

**スヌーズなし・二段確認**。一度止めても3分後にもう一度確認し、二度寝を防ぎます。アプリに**インターネット権限はありません**。端末のCalendar Providerを読み書きし、Googleとの通信は端末側のGoogleカレンダー同期機能に任せます。

Android 8.0（API 26）以上。ソースと署名済みAPKをGitHubで配布します。Playストアでの配布予定はありません。

## ダウンロード

[Releases](https://github.com/LemLame/ultimate-wake-alarm/releases/latest) から `ultimate-wake-alarm-v1.1.1.apk` を取得してください。各ReleaseにSHA-256も添付します。

旧名はWake Terminalです。公開版v1.1.0からは同じ署名鍵で上書き更新でき、設定を引き継ぎます。

初回は端末でAPKのインストールを許可し、以下の設定を行います。

1. Googleアカウントを端末に追加し、カレンダー同期を有効にする。専用アカウントでの利用を推奨します。
2. アプリの「監視を開始 / 権限を許可」で、カレンダー読取・書込と通知を許可する。
3. Googleアカウントが複数なら、監視する `primary` を選ぶ。
4. 「Google同期へのアクセスを許可」が表示された場合は、対象アカウントを選ぶ。
5. 起床アラーム通知を「高」にし、全画面表示を許可する。Android 12 / 12Lでは正確なアラームも許可する。
6. おやすみモードでアラームを許可し、電池最適化から除外する。メーカー独自の自動起動制限も確認する。
7. 「アラーム音を選ぶ」で端末内のアラーム音または音声ファイルを選ぶ。標準音も利用可能。

開発版APKと公開Releaseは署名が異なります。開発版から初めて切り替える場合は、開発版をアンインストールして公開版を入れ、初期設定をやり直してください。アプリ内設定・取り込み済み音源・確認状態はアンインストールで消えます。以後は同じ公開用署名鍵で更新します。

## 使い方

Googleカレンダーの `primary` に、タイトルが `⏰起床` で始まる時刻付き予定を作成します。例: `⏰起床 平日`。開始時刻が鳴動時刻です。終日予定やキャンセル済みの予定は対象外です。

```text
予定開始 → 本鳴動（最大アラーム音量・ループ・振動）
              ↓「起きた」1回目
          仮起床（無音・ボタン無効）
              ↓ 3分後
          再確認（60秒間鳴動・ボタン有効）
              ├「起きた」2回目 → 確定 → タイトルを「✅起きた」に更新
              └ 60秒未応答 → 本鳴動へ戻る
```

未応答なら1回目から合計4分で本鳴動に戻ります。再確認前の連打は確定になりません。本鳴動に戻った場合は、再び二段確認が必要です。確認は二段までです。

繰返し予定は該当回だけを更新します。カレンダー書込失敗時は確認済み状態と書込待ちを保持して再試行します。複数の起床予定は開始時刻順に処理し、各予定に二段確認が必要です。

選択音は再生確認後にアプリ専用領域へコピーします。元ファイルの移動・削除や再起動に依存しません。「端末の標準音」は端末の標準設定に追従します。再生不能な音源の選択は拒否し、前の設定を保持します。

## 同期遅延と運用上の制約

**数分前にGoogle側へ投入した予定は、端末への同期が間に合わず、鳴らないことがあります。** 前夜など余裕をもって登録し、アプリの「次の起床」に意図した時刻が表示されることを確認してください。

アプリは端末内の変更監視と60秒ポーリングを併用し、鳴動を `AlarmManager.setAlarmClock()` に予約します。監視中は60秒間隔を基本に `ContentResolver.requestSync()` で同期を促しますが、通信・省電力・OS・同期アダプターの制限を受けます。同期中・待機中の重複要求は避け、自動要求は自動同期設定を尊重します。「同期を要求して再読み込み」はユーザー操作としてmanual / expedited要求を送ります。

状態画面では「端末内の予定取得時刻」と「同期要求時刻」を分けます。どちらもGoogleサーバーとの同期成功を保証する時刻ではありません。Google側にだけ存在する予定を直接照合する機能はありません。端末内に今後の起床予定がない場合、読込が2分以上更新されない場合、同期設定に不備がある場合には警告します。

初回監視開始より1分以上前の予定は対象外。その後に遅れて同期された予定や停止中に到来した予定は過去24時間まで回収します。未来の予定の変更・削除は端末内変更の検出後に反映します。既に始まった二段確認は予定編集では停止しません。

再起動後は最初のロック解除後から監視を復元します。Androidの「強制停止」は予約や自動起動も停止するため、その後はアプリを開き直してください。ロック中は全画面通知を利用しますが、端末を操作中の場合はOSがヘッドアップ通知を表示することがあります。

マナーモードではアラーム用音声経路を使います。おやすみモードでアラームまで禁止されている設定を必ず解除できるわけではありません。事前にアラーム許可が必要です。メーカー独自の省電力制限、消音設定、電源断、未同期の予定などにより鳴動できない場合があります。

**大事な日は端末標準の通常アラームなどを併用してください。本ソフトウェアの利用は自己責任です。動作・起床の成功を保証しません。**

## 権限と用途

| 権限 | 必要な理由 |
| --- | --- |
| `READ_CALENDAR` | Google primaryの予定と開始時刻を端末内から読む |
| `WRITE_CALENDAR` | 起床確定時に予定タイトルを `✅起きた` へ変更する |
| `READ_SYNC_SETTINGS` | 対象アカウントと端末の自動同期設定を確認する |
| `READ_SYNC_STATS` | 同期中・待機中を確認し、重複要求を避ける |
| `FOREGROUND_SERVICE` | 監視状態を通知しながら常駐する |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14以降の専用端末向け常駐サービス種別を宣言する |
| `WAKE_LOCK` | 監視処理とアラーム再生中のCPU動作を維持する |
| `RECEIVE_BOOT_COMPLETED` | 端末再起動後に監視・確認状態を復元する |
| `VIBRATE` | 鳴動と合わせて振動する |
| `MODIFY_AUDIO_SETTINGS` | アラームストリームを最大音量にする |
| `POST_NOTIFICATIONS` | Android 13以降で監視通知・アラーム通知を表示する |
| `USE_FULL_SCREEN_INTENT` | ロック中に全画面アラームを表示する |
| `SCHEDULE_EXACT_ALARM` | Android 12 / 12Lで正確なアラームを予約する |
| `USE_EXACT_ALARM` | Android 13以降の専用アラーム用途で正確な予約を行う |
| `ACCESS_NOTIFICATION_POLICY` | おやすみモードの状態を確認し、必要な設定を案内する |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 継続監視のため、ユーザーに電池最適化除外を求める |

音声ファイルはAndroidのファイル選択画面から取り込みます。ストレージ全体の読取権限やインターネット権限は宣言していません。GoogleアカウントのパスワードやOAuthトークンをアプリが保持することもありません。

## ソースからビルド

JDK 17以上、Android SDK Platform 35、Build Tools 35.0.xが必要です。Gradle 8.10.2 / Android Gradle Plugin 8.8.2を使用します。SDK・JDKの場所を環境変数で設定してください。

```sh
./gradlew assembleDebug lintDebug
./gradlew assembleRelease
```

Windowsでは `gradlew.bat` を使用します。`assembleRelease` の出力は `app/build/outputs/apk/release/app-release-unsigned.apk` です。配布用署名鍵は同梱していません。

インストール済みSDKだけを使うWindows向けオフラインビルドも用意しています。

```powershell
.\scripts\build.ps1 -AndroidSdk $env:ANDROID_HOME -Jdk $env:JAVA_HOME
.\scripts\test.ps1 -Jdk $env:JAVA_HOME
```

オフライン経路は `app/build/offline/` に開発用APKとテスト用鍵を生成します。この鍵や中間生成物を公開しないでください。公式Releaseは別の公開配布用鍵で署名しています。

## テスト

状態機械テスト31項目、Android 15の隔離エミュレーターで統合テスト49項目、時間を短縮しないテスト50項目を確認しています。二段確認、60秒鳴動、未応答復帰、音源取り込み、旧状態の移行、OS再起動後の復元を含みます。

同期制御の正常系・頻度制限はテスト用バックエンドでも検証しています。実Googleクラウドとの同期や、各端末の物理音量を保証するテストではありません。端末ごとの実機確認が必要です。

端末テストはアプリ設定・保存状態を初期化し、テスト用カレンダーを作成します。日常利用中の端末で実行しないでください。隔離エミュレーター専用の実行補助は `scripts/device-test.ps1` です。
